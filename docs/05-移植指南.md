# 移植指南

把本工具用到你的板子上，需要动的地方按顺序列在这里。

---

## 1. 改相机引脚

编辑 `components/camera_driver/src/camera_driver.c` 里的 `camera_config_t`：

```c
cc.pin_sccb_sda  = 4;
cc.pin_sccb_scl  = 5;
cc.pin_pclk      = 13;
cc.pin_vsync     = 6;
cc.pin_href      = 7;
cc.pin_xclk      = 15;
cc.pin_pwdn      = -1;    // -1 = 未接
cc.pin_reset     = -1;
cc.pin_d0        = 11;
cc.pin_d1        = 9;
cc.pin_d2        = 8;
cc.pin_d3        = 10;
cc.pin_d4        = 12;
cc.pin_d5        = 18;
cc.pin_d6        = 17;
cc.pin_d7        = 16;
```

> ⚠️ **`pin_d0..d7` 不要照抄连接器丝印的 D0..D7**。
> 上面这组是本项目（OV2640 24P 座）的实际映射：`pin_d0` 接的是 Y2=GPIO11，而连接器上的 D0/D1 是 NC。
> 拿不准就用万用表对着原理图核一遍，或者先用官方 `esp32-camera` 示例验证引脚。

## 2. 改 SD 引脚与总线

编辑 `components/sd_files_driver/sd_files_driver.c`：

```c
sdmmc_slot_config_t slot = SDMMC_SLOT_CONFIG_DEFAULT();
slot.clk = GPIO_NUM_39;
slot.cmd = GPIO_NUM_38;
slot.d0  = GPIO_NUM_40;
slot.width = 1;                    // 1-bit
```

总线频率在 `host.max_freq_khz`：

```c
host.max_freq_khz = SDMMC_FREQ_HIGHSPEED;   // 40 MHz
```

> **40 MHz 是 3.3 V + 1-bit 的实际上限**。UHS-I（50/100 MHz）需要 1.8 V 信令 + 4-bit，不支持。
> 若不稳，退到 `SDMMC_FREQ_DEFAULT`（20 MHz），实测写入从 2.9 MB/s 降到 1.9 MB/s。

## 3. 改分辨率 / 输出格式

`components/camera_driver/include/camera_driver.h`：

```c
#define CAM_GRAY_W   96
#define CAM_GRAY_H   96
```

以及 `camera_driver.c` 里的 `cc.frame_size`（`FRAMESIZE_96X96`）。

**约束**：
- 必须是**灰度**（`PIXFORMAT_GRAYSCALE` 且 `CONFIG_CAMERA_PSRAM_DMA=y`），否则 `.gseq` 的 `1 B/px` 假设不成立
- 改尺寸后 `.gseq` 头里的 `width/height` 也要跟着改（`gseq_writer.c` 里写死 96/96）
- 越大越慢：96×96 能跑 25 fps；240×240 大约 15~18 fps；QXGA 只有个位数

> 建议**保持 96×96**：手势识别不需要更高分辨率，而且小尺寸让"帧率稳定"这件事变得容易。

## 4. 换传感器

`esp32-camera` 支持 OV2640 / OV3660 / OV5640 / OV7670 / OV7725 等。改动点：

| 项 | 说明 |
|---|---|
| `cc.pixel_format` | 若目标传感器原生支持灰度，可直接用，不需要 PSRAM DMA 压缩 |
| `CAMERA_PSRAM_DMA` | 仍建议开着（对原生灰度无害） |
| SCCB 地址 | `esp32-camera` 会自动探测，不用改 |
| 帧率 | 不同传感器差异大，务必重新实测帧间隔 |

**验证方法**：烧录后看串口 `camera_driver_info()` 打印的 PID/分辨率/格式，再用
`tools/serial_capture.py` 抓一段，确认 `帧: WxH, len=... (原生灰度)`。

---

## 5. 改类别与变量

**不用改固件**，只改 SD 卡上的 `/sd/project/config.json`（格式见 `docs/02`），重启设备即可。

只有当你想改**内置默认值**（没有 config.json 时的回落）时，才需要改
`components/cfg_store/src/cfg_store.c` 里的 `load_defaults()`。

---

## 6. 改 WiFi 行为

`components/wifi_sta/src/wifi_sta.c`：

| 想改什么 | 位置 |
|---|---|
| 重连退避档位 | `k_backoff_ms[]`（默认 200/400/800/2000/4000/8000 ms） |
| 发射功率 | `esp_wifi_set_max_tx_power(52)` → 13 dBm；电流紧张可降到 `32`（8 dBm） |
| 省电模式 | `esp_wifi_set_ps(WIFI_PS_NONE)` —— **不要删**，删了每个请求慢 190 ms |

## 7. 改录制参数

`components/capture_recorder/include/capture_recorder.h`：

```c
#define REC_RING_FRAMES      15     // 预卷帧数（0.6 s @25fps）
#define REC_MAX_FRAMES       160    // 单段上限（6.4 s）
#define REC_STATIC_FRAMES    12
#define REC_DYNAMIC_FRAMES   75
```

`REC_MAX_FRAMES` 直接决定 PSRAM 占用：`160 × 9216 ≈ 1.44 MB`。加大时注意总预算。

页面上的"每段帧数"下拉（12/24/45/75）是**会话级参数**，通过 `/api/record` 的 `frames` 字段传入，
不需要改固件。

---

## 8. 迁移检查清单

移植到新板子后，按这个顺序验证：

- [ ] 串口打印 `相机 PID=0x26`（或你那颗的 PID），分辨率/格式正确
- [ ] `帧: 96x96, len=9216 -> 原生灰度`
- [ ] `SD 挂载成功`，`/api/status` 里 `sd.mounted=true`
- [ ] 连续抓 100 帧，`ok=100`，平均帧率 ≥ 24
- [ ] 网页能打开，预览 ≥ 10 fps
- [ ] 录一段 → `gseq_dump.py` 看帧间隔是否 40±0.5 ms
- [ ] 录 10 段不重启、不报错（30 min 压测更稳）
- [ ] 删除一组后重启，`next_id` 没有回退

---

## 9. 如果你的板子没有 PSRAM

**这个工具没法用**。原因：

- 相机帧缓冲需要 PSRAM（`fb_count=3` × 85 KB）
- 录制缓冲 1.44 MB 必须放 PSRAM（内部 RAM 没那么大）
- 灰度输出依赖 `CAMERA_PSRAM_DMA`

变通方案：把 `REC_MAX_FRAMES` 降到 30 以内、`fb_count` 降到 2，全部改用内部 RAM，
并接受"单段只能录 1.2 s"。但 `CONFIG_CAMERA_PSRAM_DMA` 一旦关闭，灰度会错位——需要自己实现
YUV422→灰度 的转换。**建议直接换带 PSRAM 的模组。**
