# 配置与数据格式

## 一、`config.json`

放在 `/sd/project/config.json`，**开机解析一次**（改配置需重启设备）。

```json
{
  "version": 1,
  "types": ["thumbs_up", "fist", "victory", "palm", "ok",
            "wave", "swipe_left", "swipe_right", "circle", "none"],
  "variables": [
    { "name": "light", "max": 3,
      "labels": { "1": "warm", "2": "cool", "3": "backlit" } },
    { "name": "bg",    "max": 2,
      "labels": { "1": "plain", "2": "cluttered" } },
    { "name": "dist",  "max": 3,
      "labels": { "1": "20cm", "2": "35cm", "3": "50cm" } },
    { "name": "angle", "max": 5,
      "labels": { "1": "front", "2": "plus15", "3": "minus15",
                  "4": "plus30", "5": "minus30" } }
  ]
}
```

| 字段 | 约束 | 缺省 |
|---|---|---|
| `types` | 1~32 项，每项 ≤15 字节，不重复 | 内置 10 类手势 |
| `variables` | 0~4 个 | 内置 4 个 |
| `.name` | 1~15 字节 | — |
| `.max` | 1~32（UI 下拉上限） | 9 |
| `.labels` | 可选；键 `"1".."max"`，值 ≤15 字节 | 无 → 只显示数字 |

### 三条设计规则

**① 数据里只存数字，名字只用于显示和 PC 端还原**

- `.gseq` 里是 `var[0..3]` 四个字节，不是字符串 → 名字随便改、支持中文，都不影响已采数据
- `labels` 用**显式数字键**（不是数组下标）→ 增删项、调整顺序，**已有数据的含义都不变**

**② `max` 是防线**

服务端会拒绝越界值（`vars[i] > max` → HTTP 400），UI 也只给 0~max 的下拉。这是防"想按 2 手滑成 22"的唯一手段。

**③ `config_crc32` 是身份证**

开机对整个 `config.json` 的**原始字节**算 CRC32（zlib 兼容），写进：
- 每个 `.gseq` 头 → 每段自解释
- `directory.txt` 头部 → 索引层面也能查

**同一批数据里 CRC 不一致 = 混了配置**，PC 侧必须告警。

> 注意：CRC 按字节算，改空格、改缩进都会变。这是刻意的——它标识的是"这份文件"。

### 回落规则

| 情况 | 行为 | `crc32` |
|---|---|---|
| 文件不存在 | 内置默认（10 类 + 4 变量） | **0** |
| JSON 语法错误 | 同上 + ERROR 日志 | 0 |
| `max=999` | 夹到 32 + 告警 | 按文件实际字节 |
| `labels` 键超出 `max` | 忽略该键 + 告警 | 同上 |
| `types` 为空 | 回落默认 | 0 |

## 二、`.gseq` v3（片段文件）

小端字节序。固定头 **26 字节** + label + delta 数组 + 帧数据。

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4 | `"GSEQ"` | magic |
| 4 | 1 | `version` | 固定 3 |
| 5 | 1 | `label_len` | |
| 6 | 1 | `width` | 96 |
| 7 | 1 | `height` | 96 |
| 8 | 1 | `fps` | 标称 25 |
| 9 | 1 | `reserved` | |
| 10 | 2 | `frame_count` | u16 |
| 12 | 4 | `timestamp_ms` | 首帧开机毫秒 |
| 16 | 4 | `config_crc32` | 采集时生效的配置指纹 |
| 20 | 1 | `var_count` | 0~4 |
| 21 | 1 | `flags` | bit0=异常 |
| 22 | 4 | `var[0..3]` | 变量数字编码，0 = 未设置 |
| 26 | L | `label` | UTF-8 |
| 26+L | 2N | `delta_ms[]` | **每帧相对首帧的毫秒偏移** |
| 26+L+2N | N×9216 | 帧数据 | 灰度，行优先 |

### `delta_ms` 为什么重要

它是**唯一能发现"帧间隔不是 40 ms"的手段**。

实测中约 1% 的间隔是 80/120 ms（取帧任务被抢占），低照度下会整体退化到 ~55 ms。

**切训练窗口时必须校验**：10 帧窗口有 9 个间隔，要求全部落在 `40±4 ms`。否则窗口时间跨度会从 400 ms 变成 440~480 ms，等于教模型"同一个动作在更长时间里完成"。

按 1% 跳变率估算，`0.99^9 ≈ 91.4%` 的滑窗合格——损失可接受，但**必须过滤**。

### 文件大小校验

```
size == 26 + label_len + 2*frame_count + frame_count*9216
```

不满足就是写坏了（掉电、SD 错误）。

## 三、`directory.txt` v3（索引）

```
# esp32cam dataset index v3
# next_id=118
# cfg_crc=23491944
# name|label|v0|v1|v2|v3|frames|bytes|mtime|flags
data0117|fist|3|2|3|5|12|110646|1698800123|0
data0118|wave|1|1|2|1|75|691380|1698800157|0
```

- `#` 开头是注释
- 竖线分隔，**字段内不能含 `|`**（用数字编码天然满足）
- 一行 ~52 B；4,500 组约 235 KB
- `mtime` 是**开机计时（秒）**，不是墙上时间

### 编号规则（重要）

```
开机：next_id = max(头部 # next_id, 现存最大编号 + 1)
采集：用 next_id 建组，next_id++
删除：只删目录与索引行，**不动 next_id，不重排既有组名**
```

**删除后编号会出现空洞**（`data0003` 后面直接 `data0005`），这是**预期行为**——外部引用（PC 数据集清单、日志、人工记录）永远不会因为删除而失效。

### 读写时机

| 事件 | 是否碰 SD |
|---|---|
| 开机 | 读一次索引 + `readdir` 对账（4,500 组约 0.5 s） |
| 采集完一组 | 追加一行（**5 ms，与总组数无关**） |
| 删除一组 | 删目录 + 重写整索引（4,500 组约 1.2 s，**必须异步**） |
| 网页翻页/筛选/统计 | **零 SD I/O**（全走 RAM） |
| 回放某组 | 只打开那一个文件 |
